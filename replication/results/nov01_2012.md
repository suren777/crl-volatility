# Replication: 1 November 2012 calibrations (FTSE, S&P500, DAX)

Source scripts: `calibration_ftse.m`, `snp_cal_new.m`, `calibDAX.m` (legacy
`MATLAB/Options/logaddedparam/`). Each was run exactly as MATLAB would: same data rows,
same hard-coded `index=[...]` split (true = out-of-sample), same `S`, same weight
`w = 1./abs(bid-ask).^p`, same active `x0` line, same pricer (`mmpricer` 5-param /
`mmpricer1` 7-param) and same penalty file (`minfunc.m` = `abs_0.001` floor for FTSE and
DAX, `minfunc1.m` = no penalty for S&P500; both files resolve from the script folder
itself). FTSE/S&P500 scripts request MaxFunEvals 30000 and DAX 20000; the Python
`fminsearch` wrapper is fixed at 20000 evaluations.

## Findings

Variant 1 reproduces the published row for DAX only (in 4.38/20.61 vs 4.37/20.51, out
5.61/23.44 vs 5.60/23.42). For FTSE and S&P500 the faithful fits are *better* in-sample
than the published rows but do not match them: the published FTSE (3.30/9.62, 2.08/5.77)
and S&P500 (4.75/3.30, 4.73/3.27) rows are instead reproduced almost exactly by variants
3–5, i.e. by the k=0 Black–Scholes-with-Nelson-Siegel model, suggesting the 2014 table
numbers for those two came from a k≈0 fit (or an earlier script state) rather than from
the committed faithful runs — FTSE faithful also differs in-sample (3.63 vs 3.30 MRAE).
Every variant drives k to ≈0 (|k| ≤ 0.001, i.e. at or below the 0.001 penalty boundary),
so the fourth-moment correction contributes essentially nothing at these calibrations,
and variants 3–5 agree to the second decimal everywhere (the Taylor-4 expansion is
accurate here); only the exact variance mixture (variant 6) moves DAX visibly
(4.47/21.86 vs 4.36/20.31), which is consistent with k≈0 being small but DAX's deep-OTM
tail being Taylor-sensitive.

Anomalies found in the 2014 scripts/data: (1) `snp_cal_new.m` starts from
`x0=rand([7 1])` — a random draw — so the published S&P row depended on MATLAB's RNG
state; we seed NumPy with 0 for reproducibility, and the commented-out 5-value x0 in that
script has the wrong length for the 7-parameter `minfunc1`. (2) `SANDP500.mat` has 6
columns and the script reads T from column 5 and r from column 6, silently skipping
column 4. (3) The weight power differs between scripts: p=2 for FTSE but p=4 for S&P and
DAX. (4) `snp_cal_new.m` runs `fminsearch` once, while the FTSE/DAX scripts loop it until
fval stops changing (the loop is effectively two identical runs given
`eps=1e-29`). (5) The DAX/FTSE scripts name their split variables
`inSANDP500`/`outSANDP500` (copy-paste from the S&P script), and the DAX script keeps a
commented 6-parameter "chi" x0. (6) The out-of-sample index vectors are hand-frozen
random draws (~21/96 FTSE, 18/168 S&P, 18/96 DAX true). No legacy data files were copied
into the repo; only derived numbers are committed.
